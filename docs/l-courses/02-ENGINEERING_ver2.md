## 1. 한마디로 무엇을 했나

`corner_line/` 의 사진 2장(90도로 꺾인 실내 복도)을 보고, 사용자가 줄자로 잰 실제 치수를
받아서, 로봇 시뮬레이터(Isaac Sim)에서 쓸 수 있는 **ㄱ자(L자) 복도 3D 모델**을
Autodesk Inventor로 만들었습니다.

지킨 약속 네 가지:

- 사진에서는 **생김새만** 봅니다 — 벽이 어디 있고, 어디서 꺾이고, 어디가 뚫려 있는지. 원근 때문에 부정확하니 **길이·각도 숫자는 사진에서 재지 않습니다.**
- 모든 실제 숫자는 사용자가 채운 **측정 파일 하나**에서만 옵니다. 그게 유일한 기준입니다.
- 숫자가 상식적으로 말이 되는지 **먼저 검사**하고, 통과해야만 Inventor를 켭니다.
- 다 만든 뒤 파일을 **다시 열어서** 가로·세로·높이와 부피를 손계산값과 대조해 확인합니다.

## 2. 작업 순서 (9단계, A~I)

[[FLOW_DIAGRAM]]

말로 풀면:

1. **A · 사진 받기** — 사진 파일을 받습니다. 아직 Inventor는 켜지 않습니다.
2. **B · 생김새 분석** — 사진에서 코너 위치, 벽 면, 대칭, 뚫린 곳을 글로 적습니다. 숫자는 안 적습니다.
3. **C · 측정 요청서 만들기** — "이 모델을 만들려면 이런 길이들이 필요합니다"라는 **빈 양식**을 만듭니다.
4. **D · 사용자가 숫자 채우기** — 현장에서 잰 값을 양식에 적어 돌려줍니다. 이 파일이 기준 파일입니다.
5. **E · 숫자 검사 (통과 못 하면 여기서 멈춤)** — 형식이 맞는지, 음수가 없는지,
   "통로 폭 + 벽 두께 2개"가 다리 길이보다 짧은지 같은 상식 조건을 확인합니다.
   하나라도 틀리면 **어디가 틀렸는지 알려주고 멈춥니다. Inventor는 켜지지 않습니다.**
6. **F · 만들 순서 정하기** — 어떤 치수가 어떤 부분을 결정하는지 연결하고, 도형을 만들 순서를
   확정한 **설계표**를 만듭니다. 같은 입력이면 항상 똑같은 설계표가 나옵니다.
7. **G · Inventor로 조립** — 설계표대로 Inventor를 **자동 조종**해서 도형을 쌓고 파일로 저장합니다.
8. **H · 결과 확인** — 저장된 파일을 새로 다시 열어서: 파일이 진짜 있는지, 덩어리(부품)가
   1개 이상인지, 고장난 부분이 없는지 보고, 가로·세로·높이와 부피가 손계산과 맞는지 확인합니다.
9. **I · 보고서** — 무엇을 어떤 값으로 만들었는지, 통과/실패를 정리한 문서를 씁니다.

**두 개의 되돌아가는 화살표** (다이어그램의 점선):
빨간 점선 = 5번 검사에서 실패하면 4번(숫자 다시 입력)으로 돌아갑니다.
주황 점선 = 8번 확인에서 형상이 뭉개졌거나 고장난 도형이 있으면 6번(만들 순서 다시)으로 돌아갑니다.

## 3. 왜 프로그램이 두 종류인가

| 하는 일 | 쓰는 프로그램 | 이유 |
|---|---|---|
| 숫자 검사, 설계표 만들기 | **파이썬** | 계산이 간단하고 추가 설치가 필요 없음 |
| Inventor 조종, 결과 파일 확인 | **윈도우 파워셸 (옛 버전 5.1)** | Inventor를 프로그램으로 조종하려면 이게 무설치로 되는 유일한 길. 최신 파워셸(7)로 하면 일부 명령이 조용히 실패해서 못 씀. 스크립트가 옛 버전이 아니면 아예 실행을 거부함 |

Inventor 버전은 2027.1 을 확인했습니다. 2027 이 아니면 스크립트가 멈춥니다.

## 4. Inventor 조종 도구가 할 수 있는 것 / 없는 것

이 자동 조종 도구는 아직 기능이 제한적입니다. 그래서 L자를 "정공법"으로 못 만들고
돌아가는 방법을 씁니다.

**안 되는 것:**

- 사각형은 **항상 한 귀퉁이가 원점(0,0)에 붙은** 상태로만 그립니다. 원하는 위치에 자유롭게 못 놓습니다.
- 여러 점을 잇는 자유 곡선(폴리라인)으로 단면을 못 만듭니다.
- 복제(패턴)는 가로 방향(또는 가로+세로 동시)만 됩니다. 세로만·높이 방향은 안 됩니다.
- 모서리 둥글리기는 "바깥 세로 모서리 전체"만 됩니다.

**그래서 L자 복도는 이렇게 만듭니다** (레고 비유):
큰 덩어리를 만들고 → 안쪽 필요 없는 부분을 원점 기준 블록으로 파내고 → 바닥판과 바깥 판을 덧댄다.
아래 §5 의 8단계가 그것입니다.

## 5. L자 복도를 만드는 8단계 도형 작업

**좌표:** 원점 O = L자의 바깥쪽 뾰족한 코너, 바닥 높이. X축 = 한쪽 다리 방향,
Y축 = 다른 다리 방향, Z축 = 위.

**쓰는 값:**

| 값 이름 | 뜻 |
|---|---|
| `lane_width` | 통로 순폭 (로봇이 지나가는 빈 폭) |
| `wall_thickness` | 벽 두께 (안쪽·바깥쪽 벽 같은 값) |
| `wall_height` | 바닥에서 벽 꼭대기까지 높이 |
| `floor_thickness` | 바닥판 두께 |
| `seg_a_length` / `seg_b_length` | 각 다리의 바깥쪽 길이 (원점 O 기준) |
| `strip_width` (자동 계산) | `lane_width + wall_thickness × 2` — 벽까지 포함한 다리 전체 폭 |
| `inner_off` (자동 계산) | `lane_width + wall_thickness` — 원점에서 안쪽 벽까지 거리 |

**8단계:**

| 단계 | 하는 일 | 결과 |
|---|---|---|
| 1–2 | 벽 높이만큼 **속이 꽉 찬 L자 기둥**을 세운다 (다리 A 사각형 + 다리 B 사각형 이어붙임) | 꽉 찬 L |
| 3–4 | 안쪽을 위아래로 **관통해서 잘라낸다** (원점에 붙은 블록 2개로) | 안쪽 벽만 남음 (남은 두께 = `wall_thickness`) |
| 5–6 | L자 전체 바닥에 얇은 **바닥판**을 깐다 | 바닥 + 안쪽 벽 |
| 7–8 | 바깥 모서리(X=0, Y=0)를 따라 **바깥 벽**을 세운다 | **완성**: 바닥 + 안쪽벽 + 바깥벽, 그 사이가 통로, 양 끝 뚫림 |

바닥(5–6)을 바깥벽(7–8)보다 먼저 붙이는 이유: 나중에 붙는 조각이 항상 기존 덩어리와
겹쳐 붙어서, 따로 떨어진 조각이 안 생기게 하려고.

**만들 수 있는 조건:** `strip_width` 가 두 다리 길이보다 짧아야 하고, 바닥판이 벽보다 얇아야
합니다. 안 그러면 파낼 자리가 없어져서 그냥 상자가 됩니다.

## 6. 사용자가 부른 길이 → 모델 숫자 (헷갈리기 쉬운 부분)

사용자는 다리 길이를 **안쪽 코너(검은 벽 꼭짓점) 기준**으로 잽니다.
모델은 **바깥 코너(O) 기준**을 씁니다. 그래서 통로 폭을 더해 줍니다.

```
모델 seg_a_length = (사용자가 잰 안쪽 기준 길이) + lane_width
```

예) 큰 L: 5220 + 5450 = **10670**.
이 변환을 놓쳐서 초반에 모델을 여러 번 다시 만들었습니다.

| 파트 | 사용자가 잰 값 (안쪽 기준) | 통로 폭 | → 모델 seg_a / seg_b |
|---|---|---|---|
| `l_course_big` | 5220 / 5000 | 5450 | 10670 / 10450 |
| `l_course_small` | 1520 / 1520 | 2430 | 3950 / 3950 |

(`l_corridor_course` 와 그 스냅샷은 파이프라인 시험용이라 임의 숫자를 그대로 썼고 이 변환이 없습니다.)

## 7. 다 만든 뒤 확인하는 법

**자동 확인** (`verify_ipt.ps1`): 파일 있음 · 확장자 `.ipt` · 크기 0 아님 · 다시 열림 ·
덩어리 1개 이상 · 고장난 도형 0개.

**추가 확인** (숫자만 봐서는 형상이 뭉개진 걸 못 잡기 때문에):

- **가로·세로·높이**(물체를 딱 감싸는 상자)가 `seg_b × seg_a × wall_height` 와 정확히 같은가.
- **부피**가 손계산과 같은가.
  손계산 = (바닥판 부피) + (바깥벽 부피) + (안쪽벽 부피) − (바닥과 벽이 아래에서 겹치는 부피).
  L자 모양 면적은 "가로 사각형 + 세로 사각형 − 겹치는 정사각형" 으로 구합니다.
- **채움률**(부피 ÷ 감싸는 상자 부피)이 한 자릿수~10%대인가. 속 빈 복도면 이 정도가 정상.
  상자로 뭉개졌으면 훨씬 큽니다.

확인 결과 (전부 손계산과 세제곱밀리미터 단위까지 일치):

| 파트 | 부피 (mm³) | 채움률 |
|---|---|---|
| `l_course_big` | 25,860,025,000 | 4.9 % |
| `l_course_small` | 7,917,855,000 | 10.8 % |
| `l_corridor_course` | 6,915,150,000 | 10.5 % |

## 8. 항상 같은 결과가 나오게 하는 규칙

- 설계표 파일은 항목 순서·들여쓰기를 고정 → 같은 입력이면 글자 하나까지 똑같은 파일.
- 도형 순서는 "무엇이 무엇에 의존하는가"로 자동 정렬.
- 설계표 안에는 시간 기록을 넣지 않음 (시간은 보고서·로그에만).
- 값이 안 채워진 치수나 아직 지원 안 하는 도형 종류는 설계표 단계에서 거부.

## 9. 이 모델에 없는 것

| 항목 | 이유 |
|---|---|
| 벽 두께 정밀치 | 격실(칸막이) 구조라 정확히 못 잼 → 대충 정한 값 (100 mm 초기본 / 150 mm 큰·작은 L) |
| 바닥판 두께 | 못 잼 → 시뮬용 값 50 mm |
| 복도 끝 마감, 경사로, 모서리 둥글림 | 미포함 (양 끝 뚫린 상태) |
| 패널 분할선, 초록 띠, 걸레받이, 밝은 코너 띠 | 표면 마감이라 미포함 (따로 도면이 있어야 추가 가능) |
| 표면 무늬 · 물성 | 재질 이름표(`concrete`)만 달아둠 |

## 부록 · 용어 미니 사전

문서와 파일에 계속 나오는 영어 단어들:

| 단어 | 쉬운 뜻 |
|---|---|
| `.ipt` | Inventor 부품 파일 확장자 |
| solid / body | 속이 찬 3D 덩어리 하나 |
| extrude (압출) | 2D 도형을 위로 뽑아올려 3D로 만드는 것 |
| sketch (스케치) | 3D로 뽑기 전에 그리는 2D 도형 |
| profile (프로파일) | 스케치에서 실제로 뽑을 닫힌 면 |
| COM | 다른 프로그램이 Inventor를 조종하게 해 주는 윈도우 방식 |
| STA / MTA | 윈도우가 프로그램을 실행하는 두 가지 방식. Inventor 조종은 STA(옛 파워셸)에서만 안정적 |
| sha256 | 파일 내용이 바뀌었는지 확인하는 "지문" 같은 값 |
| bounding box | 물체를 딱 감싸는 가장 작은 직육면체 (가로·세로·높이) |
| 채움률 (fill ratio) | 물체 부피 ÷ 감싸는 상자 부피. 낮을수록 속이 비었다는 뜻 |
| 결정론적 (deterministic) | 같은 입력이면 항상 똑같은 결과가 나온다는 뜻 |
