Photo-to-IPT 사용 가이드

부품 사진으로 구조를 이해하고, 사용자가 실측한 JSON을 유일한 치수 근거로 삼아 파라메트릭 .ipt를 생성·검증합니다. 사진에서 치수를 추측하지 않습니다.

Windows 11 (네이티브) Inventor 2027 · 2027.1 (31.1) Windows PowerShell 5.1 · STA Python 3.9+ · pip 불필요 pwsh 7 (MTA) 사용 금지

1핵심 원칙

사진은 형상 가설의 근거이고, 사용자 실측 JSON은 공학적 사실입니다. CAD 피처 플랜은 오직 실측 사실에서 만들어집니다.

사진 → topology, 면, 구멍·슬롯, 축, 대칭, 반복 패턴, 기준면 후보 (구조만)

사용자 JSON → 모든 길이·직경·반경·깊이·각도·위치 (SSOT, 유일한 치수 근거)

사진› 관찰› 실측 요청› 사용자 실측› 검증된 사실› CAD 피처› IPT

금지되는 흐름  사진 → 치수 추측 → IPT

2워크플로우

Claude Code에서 /inventor-photo-to-ipt 스킬을 호출한 뒤 아래 순서로 진행합니다. 역할 표시 — 사용자 Claude 시스템 Inventor
Phase E~I(검증·플랜·빌드·검증·리포트)는 CLI 대신 GUI 앱에서도 실행할 수 있습니다 — §8 참고.

  1. Phase A 이미지 입력 사용자

    부품 사진 1장 이상을 Claude Code 채팅에 드래그·붙여넣기·경로로 첨부하고 이 부품을 Inventor 2027 .ipt로 만들어줘 라고 요청합니다. 가능하면 전면/후면/좌/우/상단을 함께 제공합니다. 이 단계에서 Inventor는 실행하지 않습니다.

  2. Phase B 구조 분석 Claude

    이미지에서 구조만 추출합니다 — 부품 유형 가설, 보이는 면, 원·구멍·슬롯, 축, 대칭, 반복 패턴, 기준면 후보, 가림/모호 영역, 관찰별 신뢰도. 시각 피처에 안정적인 ID(VF-HOLE-001 등)를 부여합니다. mm·도 값은 산출하지 않습니다.

  3. Phase C 실측 요청 생성 Claude

    필요한 치수마다 항목을 만들어 input/<part>/measurement-request.json (모든 value는 null) 과 input/<part>/feature-intent.json (파라미터↔측정 ID, 스케치 평면, 피처 순서)을 작성하고 채팅에도 JSON을 보여줍니다.

  4. Phase D 실측값 입력 사용자

    부품을 실제로 측정합니다(캘리퍼스·뎁스게이지·각도기·R게이지). 각 null을 측정한 숫자로 바꾸고 unit은 그대로 둡니다 → input/<part>/measurement-input.json (붙여넣기 또는 파일 경로).

  5. Phase E 검증 — 하드 게이트 시스템

    스키마(schemas/measurement.schema.json) → 지오메트리 일관성 순으로 검사합니다. 필수값 누락, 음수/0 두께·깊이, 구멍 직경 ≥ 면 폭, 몸체 밖 구멍 중심, 불가능한 필렛/챔퍼, 패턴 개수 < 1, 패턴 각도 (0, 360] 벗어남, 중복 ID, 단위/타입 불일치 등. 실패 시 MEASUREMENT_VALIDATION_FAILED 와 문제 ID를 반환하고 중단합니다.

    python scripts/validate_measurements.py input/<part>/measurement-input.json --report output/<part>/validation-report.json
  6. Phase F 피처 플랜 시스템

    검증된 JSON + 구조 의도에서 결정적 output/<part>/cad-plan.json (+ cad-plan.md)를 생성합니다. 모든 파라미터가 measurement ID에 연결되고, 피처는 위상 정렬되며, provenance(sha256)가 기록됩니다. 미지원 피처(shell·thread·work_plane·work_axis)와 결합되지 않은 치수는 거부합니다.

    python scripts/plan_cad.py --measurements input/<part>/measurement-input.json --intent input/<part>/feature-intent.json --out-dir output/<part>
  7. Phase G Inventor 빌드 Inventor

    Inventor 2027에 연결(없으면 실행, Visible = true)하고 p_<name> 사용자 파라미터를 단위 표현식으로 생성한 뒤 스케치·치수 구속·피처를 플랜 순서대로 만들고 Document.Update() → output/<part>/<part>.ipt 로 저장합니다. Windows PowerShell 5.1(STA) 에서 실행해야 합니다.

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/inventor_build.ps1 -PlanPath output/<part>/cad-plan.json
  8. Phase H 검증 시스템

    .ipt를 다시 열어 확인합니다 — 파일 존재, 확장자 .ipt, 크기 > 0, kPartDocumentObject, 솔리드 바디 ≥ 1, 피처 수, 상태 오류 없음. build_report 의 Result: PASS 일 때만 성공으로 봅니다.

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/verify_ipt.ps1 -IptPath output/<part>/<part>.ipt -ExpectedFeatures <n>
  9. Phase I 리포트 시스템

    output/<part>/build-report.md — 입력·provenance, 검증 결과, 파라미터 맵(M-ID → p_name → 치수 → 피처), 피처 목록, Inventor 결과, 경고, PASS/FAIL 과 output/<part>/build-log.txt (단계별 [INFO]/[WARN]/[ERROR], 예외 원문)가 생성됩니다.

3명령어 요약

모든 <part> 는 부품 이름으로 바꿉니다. Python 단계는 아무 셸에서, Inventor(.ps1) 단계는 Windows PowerShell 5.1(powershell.exe)에서 실행합니다.

스킬 호출 Claude Code 채팅에서
/inventor-photo-to-ipt

python scripts/validate_measurements.py input/<part>/measurement-input.json --report output/<part>/validation-report.json
피처 플랜 생성 Phase F · cad-plan.json / .md
python scripts/plan_cad.py --measurements input/<part>/measurement-input.json --intent input/<part>/feature-intent.json --out-dir output/<part>
Inventor 빌드 Phase G · .ipt 생성 + 검증 + 리포트
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/inventor_build.ps1 -PlanPath output/<part>/cad-plan.json
개별 .ipt 검증 Phase H · 단독 실행
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/verify_ipt.ps1 -IptPath output/<part>/<part>.ipt -ExpectedFeatures <n>
단위 테스트 Inventor 불필요 · 33건

통합 스모크 골든 픽스처 simple_plate 를 .ipt까지 E2E

4완료 조건 (PASS)

아래를 모두 만족하고 build-report.md 에 기록될 때만 PASS 입니다. 0바이트·파일 없음·바디 없음·Update 오류는 FAIL 입니다.

  • 스키마 검증 통과 (measurement.schema.json)
  • 지오메트리 일관성 검증 통과
  • cad-plan.json 스키마 + 참조 검증 통과 (DAG, 결합된 파라미터)
  • Inventor 2027 연결 — SoftwareVersion major = 31
  • 모든 계획 피처 생성 + Update() 미해결 오류 0
  • output/<part>/<part>.ipt 파일이 디스크에 존재
  • 확장자 .ipt, 파일 크기 > 0
  • 재오픈 시 문서 유형 kPartDocumentObject
  • 솔리드 바디 ≥ 1
  • 재오픈 피처 수가 계획과 일치, 상태 이상 피처 없음

5지원 범위

MVP는 단일 솔리드 기계 부품 — plate, bracket, spacer, flange, block, 회전체(shaft), 단순 하우징·마운트, 볼트 패턴 plate/flange.

구현 · 테스트 완료 피처

  • base_extrude · extrude_add · extrude_cut
  • revolve
  • hole · slot
  • fillet · chamfer
  • mirror
  • rectangular_pattern · circular_pattern

보류 — 명시적 “미지원” 오류

  • shell
  • thread
  • work_plane
  • work_axis

범위 밖 — 도면·스펙을 요청 (근사 모델 금지)

  • 자유곡면 · 유기적 형상 · 주물의 불규칙 표면
  • 사진에 보이지 않는 내부 구조
  • 스펙 없는 기어 치형 · 표준 없는 나사산
  • 공차가 지정되지 않은 정밀 끼워맞춤 결정

빌드 중지 조건 (SAFE-001)

필수 측정값 null · topology에 영향을 주는 모호한 지오메트리 · Inventor 미설치 · COM 연결 실패 · 미지원 피처 요청 · 잘못된 CAD 플랜 · 일관성 없는 측정값 · 출력 경로 쓰기 불가 · 파트 템플릿 없음 · Inventor 리빌드 오류 · 저장 실패. → 구조화된 사유와 문제 ID를 반환하고 중단합니다.

6산출물 파일 (부품별)

input/<part>/
  measurement-request.json   # 생성 · 모든 value: null
  feature-intent.json        # 생성 · 구조(파라미터↔측정 ID, 피처 순서)
  measurement-input.json     # 사용자가 값 입력
output/<part>/
  validation-report.json     # 스키마 + 지오메트리 검증 결과
  cad-plan.json              # 결정적 피처 플랜 (스키마 유효)
  cad-plan.md                # 사람이 읽는 피처 순서 + 파라미터 맵
  <part>.ipt                 # 모델
  build-log.txt              # 단계별 구조화 로그
  build-report.md            # PASS/FAIL · 파라미터 맵 · Inventor 결과
파라미터 맵 형식예 (simple_plate)
M-ID → p_<name> → 치수 → 피처 ID M001 → p_overall_width → S1 폭 → F001
M004 → p_hole_dia → F002 구멍 직경 → F002

7먼저 해볼 것 — 골든 픽스처

실제 사진 작업 전에, 합성 픽스처 tests/fixtures/simple_plate 로 파이프라인 전체가 검증된 .ipt 까지 도달하는지 확인합니다. 픽스처 치수는 테스트 데이터이며 사진에서 추정한 값과 혼동하지 않습니다.

python tests/run_tests.py
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/integration_smoke.ps1

기대 결과 — 단위 테스트 Ran 41 tests … OK, 통합 스모크 INTEGRATION: PASS (100×60×6 mm 판 + Ø8 관통 구멍 + R5 필렛, 솔리드 바디 1, 피처 3).

스모크는 산출물을 남깁니다 — output/simple_plate/simple_plate.ipt 를 열어 확인하세요. 뒤에서 정리하려면 -Clean 을 붙입니다(CI용).

8GUI 앱으로 반복하기 (Photo-to-IPT Builder)

Claude Code로 사진 분석을 1회 마친 뒤(§2 Phase A~C), 결정적 부분(Phase E~I — 검증 → 플랜 → Inventor 빌드 → 검증 → 리포트)은 터미널 대신 데스크톱 앱에서 반복할 수 있습니다. 치수를 바꿔가며 재빌드하기 좋습니다. 앱은 사진을 분석하지 않으며 API 키가 필요 없습니다 — Claude Code가 만든 input/<part>/ 폴더(measurement-request.json + feature-intent.json)를 그대로 사용합니다.

앱 흐름

  • 작업 폴더 선택 → …/input/<part>/
  • 측정 테이블의 값 컬럼만 입력
  • 검증 → 플랜 생성 → Inventor 빌드
  • .ipt 열기 / 리포트 열기
  • 산출물: <작업폴더>/output/<part>/

게이트 / 상태

  • 우측 상단 칩: Inventor 감지 녹/적
  • 플랜 버튼: 검증 통과 + feature-intent.json 존재
  • 빌드 버튼: 플랜 생성 + Inventor 감지
  • 검증 실패 행은 빨강, 취소로 빌드 중단
  • feature-intent.json 없으면 → Claude Code 안내

소스에서 실행

pip install -r requirements-dev.txt
python -m app.ipt_builder

배포용 .exe 빌드

powershell -File build/build.ps1            # --onedir (권장)  →  build/dist/Photo-to-IPT Builder/
powershell -File build/build.ps1 -OneFile   # 단일 .exe (더 큼, 백신 오탐 ↑)

build/dist/Photo-to-IPT Builder/ 폴더 전체(약 115 MB)를 압축해 배포합니다. 대상 PC마다 Inventor 2027 이 필요하며, Inventor 경로는 실행 시 레지스트리에서 자동 해석됩니다. 스펙: docs/spec/08-gui-app.md + 수동 체크리스트.

번들 자체 점검 (창 없이)

"Photo-to-IPT Builder.exe" --selftest         # import·번들·검증·플랜  →  SELFTEST: PASS
"Photo-to-IPT Builder.exe" --selftest-build   # + Inventor 빌드까지 실제로 수행

배포한 PC에서 exe가 실제로 동작하는지 한 줄로 확인합니다. GUI 실행이 모달 다이얼로그 뒤에 숨기는 패키징 오류까지 잡아냅니다.
